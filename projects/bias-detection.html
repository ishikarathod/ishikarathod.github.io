Bias Detection in Hiring Data

An end to end machine learning pipeline that reads 500+ candidate records and flags where a hiring process is treating people differently.

  • WhereCornell University
  • WhenSep 2025 to Dec 2025
  • TypeMachine Learning
500+candidate records
~90%detection accuracy
4model families compared
Detail I/R®

Context

Hiring data is full of proxies. Postcode stands in for income, school name stands in for network, a gap in employment stands in for a dozen things that have nothing to do with capability. The question was not whether bias existed in the dataset, but whether it could be detected reliably enough that a recruiting team would act on the finding.

What I built

A supervised learning pipeline over 500+ candidate records, comparing decision trees, SVM and neural networks on the same feature set so the model choice was an argument rather than a default. Feature engineering focused on separating signal that predicts performance from signal that only predicts who gets hired.

Validation

I designed experimental test frameworks and applied A/B testing and statistical analysis to check the model hypotheses rather than the model score. A classifier that is right for the wrong reason is worse than useless here, so the validation work carried as much weight as the training work.

Outcome

The pipeline reached roughly 90% bias detection accuracy. I presented the findings to both technical and non technical audiences, which meant two versions of the same story: one about precision and recall, one about which candidates the process was quietly losing.
